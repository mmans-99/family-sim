# Decisions

Newest at the bottom. Format: date — decision — why.

## SETTLED
- 2026-11-09 — The house is the whole visual world; outside is text only. — Keeps scope buildable.
- 2026-11-09 — Simulation code is separate from drawing code. — Needed for catch-up and for a future always-on version.
- 2026-11-09 — No paid AI required; commentary built from text templates. — User preference, no subscriptions.
- 2026-11-09 — Platform: web app (HTML + JavaScript), hosted on GitHub Pages from the public repo `mmans-99/family-sim`. — User choice. Pages works because the repo is public.
- 2026-11-09 — Time (first pass): 1 game hour = 2.5 real minutes, game year ≈ 28 real hours. — Superseded the same day by the entry below.
- 2026-11-09 — Time (current): both clocks run 2.5x slower than the first pass. 1 game hour = 6.25 real minutes. 1 game day = 2.5 real hours. 1 game year (28 game days) = 70 real hours (about 3 real days). Speeds: pause, 1x, 2x, 4x, and skip. — User asked for both clocks to be 2.5x longer so nothing is missed.
- 2026-11-09 — When the app is closed, the sim is not paused. On reopen, it catches up all missed time from the saved state and shows a "while you were away" summary. — User wants the family to keep living without a server.
- 2026-11-09 — Art style: pixel art. The house is a UK 3-bed semi-detached with two floors plus a back garden. — User choice.
- 2026-11-09 — Player control of the family: watch only. The player can view status, health, mood, money and history, but cannot change anything. — User choice.
- 2026-11-09 — Camera control is for viewing only. The player can turn, tilt, pan and zoom the house, but cannot change what the family does. — Keeps the watch-only rule while letting the player look around.
- 2026-11-09 — House view: a 3D dollhouse (walls, doorways, windows, stairs, furniture) rendered in a pixel-art style, with a cutaway on by default that lowers the walls nearest the camera. — User asked for the house to look like a real house with innards, plus pixel art and a cutaway.
- 2026-11-09 — The family lives in an urban UK city. Dad is a WFH software engineer on £70-80k. Mum is a stay-at-home mum. They have a mortgage and average UK bills. — User choice.
- 2026-11-09 — The world must feel life-like and keep evolving over time (ongoing events, ageing, economy, seasons), not reset or repeat. — User choice.
- 2026-11-09 — City: Birmingham (West Midlands). — User choice; the city is a single setting, so it's easy to change later.
- 2026-11-09 — Family names: Dad Tom, Mum Sarah, Oliver (5), Ruby (1). — User choice. Ages changed from 7 and 2 the same day.
- 2026-11-09 — Personalities are fully random at the start (rolled from the seed). — User choice.
- 2026-11-09 — Money uses realistic starting levels for a family who bought the house within the last couple of years (see FAMILY.md). — User choice. Sources for the figures are listed in FAMILY.md.

- 2026-11-09 — House view looks crisp, not blurry: every pixel is snapped to a fixed 10-level-per-channel palette, and each art pixel is a whole number of screen pixels. Backdrop is navy and outlines dark violet, to match the reference style the user shared. — The blurry look came from anti-aliased edges mixing in-between colours. Procedural 3D can't match hand-drawn art exactly; see OPEN for sprites.
- 2026-11-09 — Look changed to a Kairosoft-style cosy house: warm cream backdrop, dark brown outlines, wood-tile floors drawn one tile at a time, and warm window light and lamps. Furniture and rooms snap to whole grid tiles (doors one tile wide, windows one tile wide, stairs one tile per step). Key pieces are chunkier (chibi proportions). — User asked for this after rejecting the blue, blurry look. Whole tiles stop items looking awkwardly placed.
- 2026-11-09 — Hand-drawn pixel art is the goal. Art is drawn by hand as pixel sprites (I draw it, not a bought pack). Camera: free rotation. Each sprite needs drawing in four angles. — User chose this after rejecting the blurry 3D look. Trade-off: about four times the art of a fixed view; edges step while turning.
- 2026-11-09 — Drawing is pixel-exact (`raster.js`): no anti-aliasing, so every edge is on whole pixels. — The blur came from anti-aliased canvas fills.
- 2026-11-09 — Camera changed for a trial: fixed isometric tilt (about 35 degrees). The house turns in 90-degree steps with the turn buttons. One-finger drag pans. Pinch and wheel zoom. Look-down and level buttons removed. — Hand-drawn sprites from packs are drawn in fixed isometric angles, so free rotation is not practical. User asked to see the house at 90 degrees. Supersedes the free-rotation choice above if the trial is kept.
- 2026-11-09 — Art source for the hand-drawn look: the free Pixel Isometric Modern Interior pack by Cryovex (free version). Licence: commercial use and editing allowed, credit appreciated, no redistribution. User chose it. Not yet downloaded, because the build sandbox cannot reach itch.io.
- 2026-11-09 — Camera tilt changed to 30 degrees (2:1 tiles), to match the sprite pack. — The pack's floor tiles are 16 by 8 pixels.
- 2026-11-09 — Pack images are kept in `assets/cryovex/`, which git ignores, so they never reach the public repo. The game falls back to blocks without them. — Cryovex licence forbids redistribution. Revisit when the repo is private.

- 2026-11-10 — Art source changed from the Cryovex pack to the Sierrassets "Furniture pack" (flat front/side-view furniture sheet, floor and walls sheet, about 500 furniture slices). The user chose it and said its source page allows use. — The Cryovex pack is isometric, so it does not fit a flat view. The zip itself has no licence text, so redistribution rests on the user's statement; see the next entry.
- 2026-11-10 — Camera changed to a flat front/side view: no tilt, no 90-degree turns, zoom and pan only. Supersedes the 30-degree tilt and the turn buttons. — The user chose it, based on my description of the pack. That description was wrong; see the next entry.
- 2026-11-10 — Furniture is drawn with sprites from the Sierrassets furniture sheet, one hand-picked rectangle per item type (`src/render/pack.js`). About 16 sprite pixels make one grid unit. Items without a sprite stay blocks. — Keeps the flat view looking like the art; the rest of the furniture follows in steps.
- 2026-11-10 — Camera changed again: straight down, like a plan (no turn, no tilt, zoom and pan). The pack is top-down art: furniture shows its tops and floors are flat top-down tiles. Supersedes the flat front view. Each view shows one floor, since floors would overlap from above. The cutaway is off by default. — The user chose straight down after I checked the art; the earlier front-view description was my mistake.
- 2026-11-11 — House view rebuilt as a true top-down plan. The back wall (y = 0) is at the top of the screen. One grid square is always 16 art pixels (the pack's size) and zoom changes the size of an art pixel in whole device pixels. Floors use the pack's 8x8 floor tiles. — The earlier pass put sprites over a 3D block scene, picked wrong sprites and stretched them. Sprites only look right unstretched and facing the viewer.
- 2026-11-11 — Cutaway and the "All floors" view removed. — Seen from above there are no near walls to lower, and floors would cover each other. Supersedes the cutaway decision of 2026-11-09.
- 2026-11-11 — House layout changed to suit the plan view and future walking: stairs one square wide, doors moved clear of the stairs, one WC door, furniture resized to the sprites' footprints (see `data/house.json`). — The old stairs filled the hall, so nobody could have walked through it.
- 2026-11-11 — The page opens on a "Whole house" view: first floor, ground floor and garden laid out on one screen, first floor above the ground floor. Single-floor views stay as buttons. Supersedes "one floor per view". — The user wants to follow the family without changing screens. Floors are placed apart on the drawing, not stacked, because from above they would cover each other.
- 2026-11-11 — First floor rebuilt as a standard UK 3-bed semi: master bedroom front left, Oliver's room back left, Ruby's box room front right, bathroom back right, and every room opens straight off the landing. Separate shower dropped (shower over the bath, as in most UK semis); master dresser dropped for space. — User asked for a typical UK house; Ruby's room could only be reached through Oliver's. Tests now check this.
- 2026-11-11 — Ground floor fixes found by the new walking test: dining set moved off the walkway in front of the cooker and sink (three chairs for now; Ruby will get a high chair later), utility door kept at x 10-11, shoe rack removed from the foot of the stairs. — The chairs blocked the cooker, sink, fridge side of the kitchen and the utility room.
- 2026-11-11 — Pieces the Sierrassets pack lacks (stairs, stairwell, shed, tree, lawn, garden path, whole rugs, front wall face) are drawn by us in the pack's colours and outline style, by `tools/make_extras.py`, into `assets/extras/extras.png`. — The pack has no stairs, shed, tree or fence, and its rug and lawn pieces are RPG-style autotiles that do not cut cleanly into rugs. Our own art can be shared freely.
- 2026-11-11 — Tall furniture on the front wall now stands against a wall face (one square tall, with windows and the front door), drawn above the front wall. Walls, windows and fences use the pack's colours. Whole-house layout: first floor placed 8.8 squares up (was 8.5), top margin 1.1 squares. — Removes the known issue of tall sprites sticking up with nothing behind them; the spacing keeps the art pixels as big as before.
- 2026-11-11 — The first simulated person is Sarah (Mum). She is at home all day, so she shows the house in use. The others join in Phase 2. — Roadmap: one adult first.
- 2026-11-11 — Needs built: Hunger, Energy, Bladder, Hygiene, Fun, Comfort. Social waits for Phase 2. Brain: utility scoring (formula in SIMULATION.md section 0), pick among the best 3 weighted by score², potter about if nothing scores. Actions are not interrupted once started. — Simple, testable, and close to the planned design; interruptions and personality come later.
- 2026-11-11 — Actions, needs and people live in `data/` (`actions.json`, `needs.json`, `people.json`); the stairs are a `stairs` entry in `house.json` that the walking map uses. — Content in data, not code (CLAUDE.md).
- 2026-11-11 — Walking speed 8 squares per game minute (about 1.3 squares a real second at 1x). — 2 squares per minute took most of a real minute to cross the house, which was dull to watch.
- 2026-11-11 — Chores need rules: laundry at most once a game day; washing up only after cooking. — Without them the brain washed up ten times in a row.
- 2026-11-11 — People are drawn from our own sprites on the extras sheet (standing, walking step, sitting, head for lying). Seated people are drawn a little above the seat so it shows. — The pack has no people.
- 2026-11-11 — Testing aid: `index.html?minutes=N` starts the page N game minutes in, by running the same steps the clock would. Viewing only; it does not change how the family behaves. — Needed to check the drawing at different times of day without waiting.
- 2026-11-11 — Mum (Sarah) is built from Eris Esra's 16x32 character template (user supplied it): `tools/make_mum.py` paints hair, skin tone, a teal top, jeans and shoes over every idle, walk and interact frame in 5 directions (left-facing frames mirrored), and adds a sitting pose, a sleeping head and faces. Output: `assets/people/sarah.png` + `sarah.json`. — The user asked for an adult made from the template. Licence (Read Me): use in commercial and non-commercial games is allowed; free products MUST credit and link; reselling or repackaging the template (even modified) is not allowed.
- 2026-11-11 — The template files themselves are not committed (the licence forbids repackaging them); only the finished Mum sheet is. The page footer credits "Original character template created by Eris Esra" with the link. — Required for a free game; keeps the repo from becoming a copy of the template.
- 2026-11-11 — The user's "Pixelart Study - Expression Sheets" turned out to be a blank practice sheet: its 18 labelled boxes (Hollow … Shocked) all hold the same empty face, in the PNGs and in the .aseprite layers. Nothing from it is used. Four faces (content, happy, tired, uneasy, plus asleep) were drawn by us on the template's front head. — Checked by reading every layer of the .aseprite file.
- 2026-11-11 — The face shown is worked out from the needs at draw time (any need under 25: uneasy; energy under 30: tired; average 80 or more: happy; else content). Display only, not stored; real moods come in Phase 2. — Gives the faces a use now without inventing a mood system early.
